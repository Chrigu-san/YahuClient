# Yahu Client

Yahu Client is a Minecraft launcher based on [Prism Launcher](https://github.com/PrismLauncher/PrismLauncher), with its own design.
Under the hood it is still Prism, so every Prism feature works the same way: instances, mod loaders, Modrinth, Java management, import and export, and more.

## What's different from Prism

- **Block look** (`launcher/ui/themes/YahuTheme.cpp`, tokens and shapes in `launcher/ui/yahu/YahuStyle.h`): everything looks like blocks in pixel art. `YahuStyle::rounded()` gives every painted shape stepped pixel corners and `blockEdges()` the 3D edges (light top and left, dark bottom and right); the stylesheet does the same for Qt widgets with 2px borders, buttons with a thick bottom edge that sinks in when pressed, inputs sunk into the surface and progress that fills in blocks. Each kind of thing has its own block color (`blockColor()`: grass, sky, gold, amethyst, copper, diamond, redstone): the sidebar entries, the top edge of panels (`yahuTone` property: sky, grass, amethyst, gold) and red buttons that delete something (`yahuDanger`). The home banner shows a sunset with a square sun, blocky clouds and grass on dirt hills (`YahuStyle::scene`); the window background is a dark wall of blocks with colored light. Gold while a game runs. Fonts: Unbounded (headings), Silkscreen (pixel labels), Instrument Sans (text). Nothing is taken from Minecraft itself: no textures, fonts or art.
- **Color palettes** (KAN-7): *Overworld* (default: night blue with the sunset banner), *Black*, *Night Grass* (the first, moss-green look) and *Ocean* (blue with a cyan accent); the last three keep the night banner. Picked under *Settings > General > Theme*. `YahuStyle::applyPalette()` sets the tokens once at startup from the `YahuPalette` setting, before the theme builds its stylesheet, so a change shows after a restart. A new palette is one more entry in `YahuStyle::palettes()`.
- **Custom icon set** (`launcher/resources/yahu/icons`, generated by `generate.py`).
- **App shell**: a narrow icon rail with a sliding marker in `YahuSidebar`, a still backdrop in `YahuBackdrop` (the block wall, drawn once per size; the fireflies are gone), a small click effect in `YahuFxLayer` (a white pixel square that opens up and fades in a quarter of a second, a bigger one for Play), and the hero banner in `YahuHero` / `YahuPlayButton`: a pixel landscape with parallax (sunset or night, see the block look) where the selected instance's icon floats gently over the hills with a soft shadow on the ground. Kept simple on purpose: a turning icon and a pixel aura were tried and looked cheap.
- **No progress window when starting** (`launcher/LaunchProgress.cpp`): the launch no longer opens a window with progress bars. `LaunchController::onProgressRequested` sends the start's status and progress to `LaunchProgress`, and the banner shows one quiet line right under the Play button ("Downloading libraries, 42%, about 12 s left", the time estimated from the progress so far) and a thin grass bar along the banner's bottom edge. Once Java starts it says "Starting Minecraft" for a moment, then the line goes.
- **Instance cards** (`launcher/ui/instanceview/InstanceDelegate.cpp`): flat blocks that fade in staggered and lift a little on hover. The icon sits in a sunk-in slot like an inventory item; the selected card (gold while playing) gets a frame on the inside. "Last played" reads like "2 days 5 hours ago" (`Time::relativeAgo` in `launcher/MMCTime.cpp`).
- **Single window** (`launcher/ui/yahu/YahuSheetHost.cpp`): dialogs and secondary windows appear as frameless overlays over the main window, as a full page or a card. Behind a card the launcher is drawn from a snapshot and dimmed, because Windows doesn't reliably make these overlay windows see-through. Overlays are always parented to the top-level window: parenting one to a child widget made Qt give that part of the launcher native windows, and the click-effect layer (`YahuFxLayer`) then swallowed every real click while Minecraft ran (KAN-12). `main.cpp` also sets `AA_DontCreateNativeWidgetSiblings`, and the effect layer answers `WM_NCHITTEST` with `HTTRANSPARENT`, so this can't come back.
- **Servers tab** (`launcher/ui/yahu/YahuServersPage.cpp`, `launcher/ui/dialogs/ServerSettingsDialog.cpp`): see below.
- **Shop tab** (`launcher/ui/yahu/YahuComingSoon.cpp`): a preview of the cosmetics shop, not functional yet.
- English by default, no setup wizard (except for Java problems), no external links, one theme only. Own name, icon and data folder (`%APPDATA%\YahuClient`).

## Server hosting

`launcher/servers/ServerManager.cpp` keeps every server in `<data>/servers/<name>/` with its settings in `yahu-server.json`.

- Paper, Vanilla and Fabric are downloaded from their official sources; a fitting Java is picked by Minecraft version.
- `server.properties` is rewritten from the settings on every start; keys Yahu Client doesn't manage stay untouched.
- New servers start with a view distance of 24 chunks (vanilla uses 10); servers that already exist keep theirs.
- Closing the launcher saves and stops every running server (`ServerManager::shutdown`, called from `MainWindow::closeEvent`).
- A server never outlives the launcher (`launcher/servers/ServerProcesses.cpp`): every server process goes into a Windows job with `KILL_ON_JOB_CLOSE`, so when the launcher crashes or is ended in the task manager, Windows ends its servers too. Before that, such a server kept running unseen and held its folder and port; deleting failed with "could not be moved to the recycle bin".
- Servers left running by older versions are found through the Restart Manager (the Java process that has `server.jar` open). Starting the server first stops the old one with Ctrl+C, so it saves its world like after `stop`; deleting the server ends it right away.

**No port forwarding** (`launcher/servers/PortMapper.cpp`): while a server runs, Yahu Client asks the home router via UPnP (IGD) to forward its TCP port.

1. Search: SSDP `M-SEARCH` to `239.255.255.250:1900`, sent on **every** network adapter (Windows otherwise picks a virtual one from WSL or Hyper-V and the router never hears it).
2. The router's device description gives the `WANIPConnection` / `WANPPPConnection` control URL.
3. `AddPortMapping` with a one-hour lease, renewed every 50 minutes; routers that only allow permanent mappings (error 725) get lease 0.
4. `GetExternalIPAddress` shows the address for friends. An address in a private range or `100.64.0.0/10` means CGNAT or a second router: the page says friends can't reach this PC directly.
5. `DeletePortMapping` when the server stops or the launcher quits.

When the router has no UPnP or refuses (e.g. error 718, port taken by another device), the Servers page explains it and falls back to the manual port-forwarding hint. The first server start triggers the Windows firewall prompt for Java; it has to be allowed.

Tested with a Sagemcom F3896LG (Sunrise). Not covered yet: networks without any public address. That needs a relay server (planned on `yahuclient.net` with a small VPS).

**Server addresses** (`launcher/servers/AddressService.cpp`): every server can have a name, so friends join with `chris.yahuclient.net` instead of an IP.

- The name is set under *Address* in the server settings; a new server suggests the signed-in player's name. Typing is cleaned up as you go (lowercase, spaces become dashes), and the dialog says next to its buttons why it can't be saved yet (missing name, bad address, EULA not ticked).
- The Servers page shows the address big, with a small Copy button, and one short line about the state underneath (KAN-11). The LAN address is gone from the page.
- **Joining your own server by its name:** most home routers can't reach their own public address from inside (no NAT loopback), so on the hosting PC the name would fail with "Connection refused". `launcher/servers/LocalHosts.cpp` adds `127.0.0.1 <name>.yahuclient.net # Yahu Client` lines to the Windows hosts file, for all servers at once. There is no button for it: as soon as a server's address is live, `ServerManager::pointNamesHere` asks Windows (one UAC prompt) by itself if the name doesn't lead to this PC yet. It asks at most once per name while the launcher runs; a "No" is noted in the server console and asked again after the next launcher start. Minecraft still gets the port from the SRV record. Lines without the marker are never touched. Other PCs in the same home network still need the router to support NAT loopback.
- Once the router port is open, the launcher asks the address service (`services/dns-worker`, a Cloudflare Worker at `api.yahuclient.net`) to point the name at this PC. The first time it claims the name and keeps the returned secret in `yahu-server.json` (`addressSecret`).
- A port other than 25565 gets an SRV record, so friends never type a port. The Servers page shows and copies the name instead of the IP.
- Renaming or deleting a server gives the old name back. A name somebody else has shows as taken.
- No address is set up on CGNAT connections (nothing could reach them anyway).

The Cloudflare API token lives only in the worker as a secret; see `services/dns-worker/README.md` for the API, tests and deployment.

## In-game mod (KAN-4, `mod/`)

A Fabric mod (`yahu`, client only) for Minecraft 26.3, built with Gradle and Fabric Loom 1.19 against the versions Fabric instances for 26.3 ship (loader 0.19.5, Fabric API 0.164.0); it needs Java 25. 26.x is unobfuscated, so there are no mappings. The launcher ships `mods/yahu-mod.jar` and copies it into an instance before it starts (`launcher/minecraft/YahuMods.cpp`), but only into Fabric instances for 26.3 that have Fabric API: without Fabric API the game would refuse to start. An older copy is replaced, the instance log says what happened.

- **Look: smoked glass on a dark night** (`ui/Glass`, `ui/Theme`, `ui/Draw`, `ui/Background`, `ui/Icons`, `ui/Spaced`): in the spirit of the big PvP clients. Behind every menu the picture (the game, or the title panorama) is blurred by Minecraft's own menu blur (at least 9, `OptionsBlurMixin`; 0 stays off) and drowned in a deep blue night (`Background.tint`, also over the create world header, `CreateWorldScreenMixin`), so its colors (the new panorama is warm orange) never shout through. On that, slim panes of smoked glass: a translucent slate fill, a fine light edge one screen pixel thin that is a touch brighter along the top, 3 px corners; our own entries are glass tinted violet. Labels of the main and pause menu are spaced capitals (`ui/Spaced`, letters placed on whole screen pixels; the spacing tightens on narrow buttons, trailing dots are dropped). Everything is drawn in real screen pixels (`ui/Draw`): corners and dots from disk and ring textures made for exactly their size, icons and the logo as signed-distance shapes painted for the exact size they are shown at with 4 samples per pixel (`Tex.shape`, `ui/Icons`). Text is crisp: the Yahu fonts exist once per GUI scale (`assets/yahu/font/ui_N`, `display_N`, `heading_N`, rasterized at N screen pixels per GUI pixel, chosen by `Theme.uiFont()`), so glyphs land 1:1 on screen pixels instead of being scaled; they are sampled linearly (`FontTextureMixin`) and menu text has no hard drop shadow (`GuiTextRenderStateMixin`). Instrument Sans for text, Unbounded for headings (TTF, OFL licensed; the license texts are `font/ofl-*.txt`).
- **Yahu menu** (`ui/YahuScreen`): the **Yahu Mods** button (tinted glass) in the button column, under Realms on the title screen and under Back to Game in the pause menu, or Right Shift to open it (`InputConstants.KEY_RSHIFT`; 26.x has its own key codes). It closes with Esc (no "press Esc" text, no extra buttons). Full screen over the blurred background: on the left a floating glass sidebar with the mods (a color square, name, switch; the selection is a frosted pill that glides), on the right the chosen mod's name, state, a live preview and its settings in glass cards, scrolling smoothly. Controls (`ui/Control`): sections, toggles (flat switches with a square knob), sliders (thin line and a slim knob), choices (a glass field with a frosted highlight sliding to the choice), color dots, glass button rows that wrap, notes. Settings are saved to `config/yahu.json`; older files are upgraded.
- **Minecraft's own screens** (`mixin/`, drawing in `ui/BlockWidgets` and `ui/ModernSprites`): buttons are glass that frosts brighter with a light edge on hover, sliders fill with a brighter frost up to the value and have a slim white knob, text fields are a darker pane whose edge lights up while typing, checkboxes are glass (white when ticked), the chosen tab is a frosted pill, list rows select with a glass pane (`SelectionListMixin`), scroll bars are thin white pills (`GuiGraphicsExtractorMixin` on `blitSprite`). Menu text uses the Yahu UI font (`ui/MenuFont`): while a screen is built and drawn (`ScreenMixin` around `init` and `extractRenderStateWithTooltipAndSubtitles`), text without a font of its own is measured (`StyleMixin`) and recorded (`GuiTextRenderStateMixin`) in Instrument Sans, so labels fit and center; chat, HUD and text in the world keep Minecraft's font. The title screen shows a **YAHU / CLIENT** word mark instead of the Minecraft logo (`TitleScreenLookMixin`) and no splash text (`SplashRendererMixin`).
- **Main menu layout** (`ui/TitleLayout`): centered and calm. The Yahu logo (a hexagon outline with a geometric Y and a violet spark where its arms meet, `Icons.LOGO`) with the word mark YAHU CLIENT in spaced capitals under it (`TitleScreenLookMixin`, instead of the Minecraft logo; no splash text, `SplashRendererMixin`), then a short column of slim glass buttons (Singleplayer, Multiplayer, Realms, buttons other mods add like Mod Menu's "Mods", Yahu Mods in violet). Settings is a gear icon button in a row at the bottom with Minecraft's own small buttons; Quit is a close X in the top right corner. Under the mouse a button's fill and edge brighten. It moves and restyles the widgets the screen built (after `ScreenEvents.AFTER_INIT`), so every button keeps working, including ones from other mods. The pause menu keeps its layout but gets the same buttons (`TitleLayout.restyle`). The mixins are not required (`defaultRequire: 0`), so a clash with another mod can't crash the game.
- **Crosshair** (`crosshair/`): replaces the vanilla crosshair through `HudElementRegistry.replaceElement` while it is on. Drawn in real screen pixels whatever the GUI scale, so a 1 px line is 1 px. Built from parts that combine: arms (none, cross, T, X) with length, thickness and gap (the gap may go below zero), a center dot of any size (round as a smooth disk, or square, own color optional) and a ring (radius, thickness). Color, opacity, outline width, color and opacity. Presets: Classic, Dot, Pro, Circle, Big. PvP: another color while aiming at a player or mob, a hit marker (color, size, time), the attack charge as a bar or a ring, and a spread that opens it while moving. `CrosshairGeometry` builds the rectangles, so the shapes are tested without a game.
- **Lyrics** (`lyrics/`): karaoke for the song playing anywhere on the PC.
  - `now-playing.ps1` reads the Windows media session (Spotify, browsers, any app in the Windows media overlay) and prints title, artist, album, length, position and play state as JSON lines; `MediaWatcher` keeps it running while the mod is on; the script stops by itself when the game that started it is gone (closed or crashed). The position is extrapolated between reports.
  - `LyricsService` asks [LRCLIB](https://lrclib.net) for time-stamped lyrics (exact match with the song's length first, then a search), once per song. Nothing is bundled: the mod and the repository contain no song texts (the tests use made-up lines).
  - `SyncedLyrics` reads LRC, including enhanced LRC with a stamp per word; without word stamps the line's time is spread over the words by their length.
  - `LyricLayout` places the words: wrapped into centered rows within the line width (a share of the view, so a long line never runs off; the sky and the screen convert it differently), or for **Kinetic** stacked like a poster, each word with its own size and tilt from a pattern picked by the line, big words on a row of their own.
  - `LyricsPainter` animates them, the same in the sky and on the screen: **Line** colors the sung part in letter by letter, **Word by word** pops each word in when it is sung (scale with a little overshoot, rising, fading in), **Kinetic** does the same on the poster layout. Settings: font (Minecraft, Unbounded, Instrument Sans, Bebas Neue, Archivo Black, Righteous, Pacifico, Bungee, Silkscreen; the new ones are OFL fonts from Google Fonts, `font/lyrics_*.json`), size, height, line width, pop strength, outline width (0 to 3 font pixels in quarter steps) and color, sung and text colors, a gradient along the line to a color of its own, uppercase, next line, song title. **Looks** are ready-made combinations of typeface, colors and outline: Clean, Neon, Sunset, Poster, Dreamy, Arcade, Retro.
  - The outline is copies of the text around a circle of the outline's width (`OutlineRing`, 8 to 16 copies), so it is equally thick in every direction at any width. In the sky the copies sit a little behind the text (`SkyWorldRenderer.OUTLINE_DEPTH`) instead of in its plane, where they fought over the same depth and flickered as the camera moved.
  - Where: **In the sky** (default, `SkyWorldRenderer`, drawn in the level render 20 blocks away at a fixed compass direction and height, placed relative to the camera so it hangs like a cloud; `SkyAnchor` moves it in front only when a new line starts out of view) or **Follow view** (`SkyLyricsRenderer`, on the screen).
- **Skybox** (`skybox/`, `mixin/SkyRendererMixin`): replaces the sky (color, sun, moon, stars) with a cube-map cube, drawn like the End's sky with the `END_SKY` pipeline. Built-in skies are painted by the mod itself pixel by pixel from the viewing direction (`SkyboxGenerator`, value noise and math, no outside pictures): Black hole (bent starlight, a photon ring, a glowing tilted disk and its arc over the top), Clear day, Golden hour, Aurora night, Nebula. Your own pictures go into `config/yahu/skyboxes` (Open folder in the menu): a panorama twice as wide as high, or a cube cross 4 by 3. Painting runs in the background, then the atlas (3 by 2 faces, each with a border painted from beyond its edge so filtering never shows seams) is uploaded. Settings: brightness, rotation, darker at night (follows the normal sky's brightness), overworld only, clouds (off by default under a custom sky: `CloudRendererMixin` skips both ways Minecraft draws them while the custom sky is up). The menu shows a small panorama preview.
- **Inventory** (`inventory/InventoryLook`): the hotbar and the simple inventories in a look that matches the menus, in four styles (Glass, Minimal, Neon, Soft) with an accent color, opacity and slot roundness, and presets (Glass, Clean, Neon, Candy, Toxic). The hotbar, its selection, the offhand slot and the slot highlights are Minecraft sprites, swapped in `ui/ModernSprites`. The panels of the player's inventory, chests, shulker boxes, dispensers and hoppers are textures that are nothing but a panel and slots: their blit is skipped (`GuiGraphicsExtractorMixin`) and a panel with a slot under every slot of the menu is drawn instead (`AbstractContainerScreenAccessor` for the position), so it fits a chest of any size; the inventory gets its player frame and crafting arrow back. Their titles turn light (`ContainerLabelsMixin`) only on screens that were redrawn. Other blocks (furnaces, anvils, ...) keep Minecraft's look.
- **In-game test** (`src/gametest`, `gradlew runClientGameTest`): starts the game and takes screenshots of the title screen, options, every page of the Yahu menu, the crosshair, the lyrics in every style (made-up lines), a lyrics look preset, every built-in sky, the inventory with a few items, the hotbar and the pause menu. Live lyrics stay off there.

Build it before the launcher's install step (the install takes `mod/build/libs/yahu-mod.jar` if it is there):

```bat
cd mod
set JAVA_HOME=%APPDATA%\YahuClient\java\java-runtime-epsilon
gradlew build
```

`gradlew build` also runs the unit tests (LRC parsing and word times, layout and wrapping, crosshair geometry, sky painting and seams, sky anchor).

## Building (Windows)

You need: VS 2026 Build Tools (C++), Qt 6.11.2 `msvc2022_64` (with qtimageformats and qtnetworkauth) under `C:\Qt`, CMake, Ninja and JDK 17.

```bat
scripts\yahu-build.bat
```

The result ends up in `install\yahuclient.exe`.

## Tests

Tests live in `tests/` (Qt Test, one `LauncherTests` executable). Yahu's own:

- `PortMapper_test.cpp`: a fake router on localhost answers the UPnP calls; covers opening, the lease fallback, refused and taken ports, CGNAT detection, closing, stopping while opening and parsing router descriptions.
- `YahuServer_test.cpp`: server settings round trip through JSON, `server.properties` writing and escaping, install state.
- `RelativeTime_test.cpp`: the "2 days 5 hours ago" texts.
- `AddressService_test.cpp`: a fake address service; covers claiming, updating, taken names, lost secrets, offline service and name rules.
- `LocalHosts_test.cpp`: reading and rewriting the hosts file without touching other lines, dropping anything that isn't a host name.
- `YahuMods_test.cpp`: which instances get the Yahu mod (Fabric, Minecraft 26.3 or 26.3.x, Fabric API present).
- `ServerProcesses_test.cpp` (needs `java` on the PATH, Windows only): a small Java program stands in for a server; covers finding the process that holds `server.jar`, stopping it so its shutdown hook (the world save) runs, and that a tied server ends when its launcher is killed.

The address service has its own tests: `cd services/dns-worker` and `node --test`.

Run them from the build folder with Qt's `bin` on the `PATH`:

```bat
set PATH=C:\Qt\6.11.2\msvc2022_64\bin;%PATH%
cd build
ctest -C Release --output-on-failure
```

Prism's `FileSystem` test currently fails on Windows; it is unrelated to the Yahu code.

## Releasing

1. Bump `Launcher_VERSION_MAJOR/MINOR/PATCH` in `CMakeLists.txt` (through a pull request).
2. Build the mod (`mod\gradlew build`, see above), then the launcher, then install into `install\` (`cmake --install build --config Release --prefix install`); the install puts the mod into `mods\`.
3. Make the installer with [NSIS](https://nsis.sourceforge.io): copy `install\` to `build\stage\`, add the VC++ runtime DLLs from `VC\Redist\MSVC\<version>\x64\Microsoft.VC145.CRT`, then run from `build\stage\`:
   ```bat
   makensis -NOCD ..\program_info\win_install.nsi
   ```
   This writes `build\YahuClient-Setup.exe` (script template: `program_info/win_install.nsi.in`).
4. `gh release create vX.Y.Z build\YahuClient-Setup.exe --title "Yahu Client X.Y.Z" --notes-file <notes>`.

The link `https://github.com/Chrigu-san/YahuClient/releases/latest/download/YahuClient-Setup.exe` always points at the newest installer.

## Working together

- `main` is protected: changes only through pull requests (also for admins), no force pushes, open review conversations block the merge.
- Branches: `<type>/<TICKET>-<short-name>`, e.g. `feature/KAN-12-cosmetics-shop` (types: `feature`, `fix`, `ui`, `chore`, `docs`).
- Commits in English, imperative summary line, Jira key first when there is a ticket.
- **Every change updates the docs in the same pull request**: this file, `README.md` and the Discord texts in `discord/` (player features and history in `features.md`, team rules in `dev-workflow.md`).

## Microsoft login (required for playing)

Prism's Microsoft client ID belongs to Prism and must not be used in a rebrand. Yahu Client needs its own:

1. In the [Azure Portal](https://portal.azure.com) → *App registrations* → *New registration*:
   - Supported account types: **Personal Microsoft accounts only**
   - Redirect URI: platform **Mobile and desktop applications**, URIs `http://localhost` and `yahuclient://oauth/microsoft`
   - Under *Authentication*, turn on **Allow public client flows**.
2. Copy the **Application (client) ID**.
3. Request access to the Minecraft API from Mojang for this client ID (form: <https://aka.ms/mce-reviewappid>). Until Mojang approves it, login fails at the "Minecraft profile" step.
4. Enter the ID either:
   - in the launcher under *Settings → APIs → Microsoft Authentication* (no rebuild needed), or
   - in `CMakeUserPresets.json` as `Launcher_MSA_CLIENT_ID` and rebuild.

`CMakeUserPresets.json` is listed in `.gitignore`, so keys never end up in the repo.

## CurseForge

The CurseForge API key is also Prism's and has been removed. Modrinth works without a key. For CurseForge, request your own key at <https://console.curseforge.com> and enter it under *Settings → APIs*.
